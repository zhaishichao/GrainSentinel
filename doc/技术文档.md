# 粮情哨兵智能体 · 技术文档

## 一、总体设计

粮情哨兵智能体是一套「自然语言入口 + 多智能体协同 + 领域数据工具」的粮食安全分析系统。
系统分为三层：

```
┌──────────────────────────────────────────────┐
│  表现层  static/  DeepSeek 风格前端           │
│          index.html / style.css / app.js      │
├──────────────────────────────────────────────┤
│  服务层  app.py   FastAPI + SSE 流式接口      │
│          /api/chat  /api/overview  /api/agents │
├──────────────────────────────────────────────┤
│  智能层  agent/   自研多智能体框架            │
│          llm.py + core.py + build.py          │
│  数据层  data/    领域工具（纯函数）           │
└──────────────────────────────────────────────┘
```

## 二、多智能体框架（agent/core.py）

框架由三个核心抽象组成，总计约 200 行：

### 2.1 Tool（工具）

```python
@dataclass
class Tool:
    name: str          # 工具名，供 LLM 决策调用
    description: str   # 工具描述，写入提示词
    func: Callable     # 实际执行函数（支持 async / 同步纯函数）
    needs_emit: bool   # 是否需要注入 emit 回调（委派类工具）
```

### 2.2 Agent（智能体）

- 每个智能体持有：`name`、`role`、`system_prompt`、`tools`；
- 通过 **ReAct 循环** 执行任务：`思考 → 调工具 → 观察 → 再思考`，最多 `max_tool_rounds` 轮；
- **两阶段输出**：工具循环阶段用非流式 `complete()`（稳定），最终回答用流式 `stream()`（体验好）。

### 2.3 Supervisor（主控）

- 继承自 `Agent`，通过 `_delegate_tool()` 把每个子智能体封装为 `ask_<name>` 工具；
- 实现「子智能体即工具」的层级委派，与主流平台的 subAgent 模式一致；
- 子智能体被委派时以 `stream_text=False` 运行，产出精炼调研结论供主控汇总。

### 2.4 决策协议

LLM 通过结构化 JSON 决策，不依赖原生 function-calling：

```json
{"action": "tool", "tool": "get_grain_condition", "args": {"warehouse": "储备库C"}}
{"action": "finish", "plan": "一句话概述分析思路"}
```

`parse_json()` 稳健提取 JSON（容忍代码块包裹与前后杂文），兼容任意 OpenAI 兼容模型。

## 三、事件协议与流式输出（app.py）

后端使用 `asyncio.Queue` + 后台任务解耦「智能体执行」与「SSE 推送」，定义四类事件：

| 事件类型 | 含义 |
|---------|------|
| `agent` | 智能体开始执行（名称 + 职责） |
| `tool` | 智能体调用工具（工具名 + 参数） |
| `tool_result` | 工具返回结果（预览片段） |
| `text` | 最终回答的流式文本增量 |
| `error` / `done` | 异常反馈 / 结束标记 |

前端 `app.js` 通过 `fetch + ReadableStream` 解析 SSE 帧，逐字渲染回答并同步展示「思考过程」轨迹。

## 四、领域数据模型（data/mock_data.py）

### 4.1 库点与仓型

| 库点 | 仓型 | 品种 | 储粮状态 |
|------|------|------|---------|
| 直属库A | 平房仓 | 小麦 | 宜存 |
| 直属库B | 浅圆仓 | 稻谷 | 宜存（充氮气调） |
| 储备库C | 立筒仓 | 玉米 | 轻度不宜存 |

### 4.2 领域工具（8 个纯函数）

| 工具 | 说明 |
|------|------|
| `get_grain_condition` | 粮温/水分/仓湿/气体浓度 + 风险研判 |
| `get_quality_inspection` | 品质指标 + 储存品质判定 |
| `get_quality_limits` | 国标限量（GB 2761 毒素 / GB 2762 重金属） |
| `get_pest_monitor` | 虫害密度分级 + 熏蒸/气调建议 |
| `get_storage_control` | 通风/气调/谷物冷却 + 损耗评估 |
| `get_reserve_rotation` | 宜存判定 + 轮换计划 |
| `assess_risk` | 综合风险评分 + 分级预警 + 处置预案 |
| `get_overview` | 前端可视化面板数据 |

### 4.3 数据贴近国标

- **安全水分**：小麦 ≤12.5%、稻谷 ≤14.5%、玉米 ≤14.0%；
- **真菌毒素（GB 2761-2017）**：黄曲霉毒素 B1 玉米/稻谷 20 μg/kg、呕吐毒素 1000 μg/kg、
  玉米赤霉烯酮 60 μg/kg；
- **重金属（GB 2762-2022）**：铅 0.2、镉 0.2、无机砷 0.2、汞 0.02 mg/kg；
- **虫害密度分级**：≤5 头/kg 基本无虫、5~30 头/kg 一般虫粮、>30 头/kg 严重虫粮；
- **储存品质判定**：宜存 / 轻度不宜存 / 重度不宜存。

## 五、测试（tests/test_agent.py）

用 `StubLLM` 注入预设的「工具调用脚本」，无需真实 Key 即可验证：

1. `test_parse_json` — JSON 决策解析鲁棒性；
2. `test_mock_data` — 领域数据与工具函数正确性；
3. `test_agent_tool_loop` — 单智能体 ReAct 循环与事件发出；
4. `test_supervisor_delegation` — 主控委派子智能体再调用工具的完整链路；
5. `test_supervisor_registry` — 6 个子智能体委派工具注册。

## 六、可扩展性

所有领域工具均为纯函数，替换为真实数据源（粮库智能化改造平台 / 粮情测控传感器网关 /
检测实验室 LIMS）时无需改动 Agent 框架与前端；模型层通过 OpenAI 兼容协议可插拔切换。
