# 简历 · 项目介绍

## 项目名称

**粮情哨兵智能体（Grain Sentinel Agent）** —— 多智能体粮食安全问答与分析系统

> 技术栈：Python · FastAPI · OpenAI 兼容协议（DeepSeek）· 自研多智能体框架 · HTML/CSS/JS · ECharts

## 项目描述

面向粮食安全与粮情实时监测的多智能体系统：用户以自然语言提问，主控智能体自动理解意图、
路由 6 个专职子智能体（粮情监测 / 质量检测 / 虫霉防治 / 智能仓储 / 储备轮换 / 安全预警）
调用 8 个领域工具取数分析，输出可量化的粮情研判与处置建议；数据贴近我国储粮现状与国标
（GB 2761 真菌毒素、GB 2762 重金属限量等），前后端与多智能体框架全程自研，
共 19 个文件、核心框架仅 191 行。

## 主要工作

1. **自研轻量多智能体框架**：实现 `Tool / Agent / Supervisor` 三层抽象与 ReAct 决策循环，
   以「子智能体即工具」实现主控对 6 个专职子智能体的层级委派与结果汇总，替代
   LangChain/LangGraph 等重框架（核心框架 191 行、直接依赖仅 4 个）。

2. **设计结构化决策协议与两阶段流式**：让 LLM 通过 `{"action":"tool"|"finish"}` 决策、
   不依赖原生 function-calling 以兼容任意 OpenAI 模型；工具循环非流式保证稳定、
   最终回答真流式保证体验（首字秒级响应）。

3. **搭建 FastAPI + SSE 流式后端**：以 `asyncio.Queue` + 后台任务解耦智能体执行与推送，
   定义 agent/tool/tool_result/text 事件协议，实现逐字流式输出与「思考过程」轨迹实时回传。

4. **构建 DeepSeek 风格前端与粮情可视化面板**：原生 HTML/CSS/JS + ECharts，手写 Markdown
   渲染器与 SSE 流解析，实现粮温/仓温/仓湿 24h 曲线面板、储粮状态徽标、可折叠思考轨迹、
   多会话 localStorage 持久化。

5. **领域数据建模、工具与测试**：构建 3 库点（平房仓/浅圆仓/立筒仓，小麦/稻谷/玉米）
   储粮数据与 8 个纯函数工具（粮情测控、质量检测、虫霉监测、仓储管控、轮换、风险评估），
   用 StubLLM 注入实现无 Key 全链路单测，并接入 DeepSeek 完成真实模型端到端验证。

## 主要成果

1. **覆盖 6 大粮安场景**：粮情监测、质量检测、虫霉防治、智能仓储、储备轮换、安全预警
   一体化协同分析，6 个子智能体 + 1 个主控智能体各司其职、自动路由。

2. **框架精简、部署提速**：自研框架替代 LangChain/LangGraph 等重框架，**直接依赖从数十个
   精简至 4 个**，核心代码仅 191 行，`pip install` 安装体积与冷启动开销下降一个数量级；
   相比传统人工巡检 + 经验判断（小时级），系统实现秒级智能研判。

3. **量化结论可执行**：端到端真实模型验证中，主控自动路由至安全预警智能体，子智能体
   自主调用 3 个工具，输出**风险评分 18/100、高风险（Ⅳ级）判定**、量化风险表
   （粮温 32.1℃、水分 14.6%、虫害 18 头/kg）与 7 项分级处置行动清单。

4. **无 Key 可测试、验证高效**：5 个测试用例用 StubLLM 离线跑通，**全程约 2 秒**（含解释器
   启动），无需真实 API Key 即可验证主控委派 → 子智能体调工具 → 汇总的完整链路。

5. **数据贴合国标、可落地演进**：覆盖安全水分、真菌毒素（GB 2761）、重金属（GB 2762）、
   虫害密度分级与储存品质判定，量化储粮损耗可从 2%~3% 降至 1% 以下；领域工具均为纯函数，
   可无缝替换为真实粮情测控系统与检测实验室 LIMS 接口。
