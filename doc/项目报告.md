# 粮情哨兵智能体 · 项目报告

## 一、项目概述

**粮情哨兵智能体（Grain Sentinel Agent）** 是一套面向「粮食安全、粮情实时监测、仓储数据问答」的
多智能体问答/分析系统。用户以自然语言提问，主控智能体自动理解意图，路由 6 个专职子智能体
（粮情监测 / 质量检测 / 虫霉防治 / 智能仓储 / 储备轮换 / 安全预警）调用领域工具取数分析，
输出可量化的结论与可执行的处置建议。前后端与多智能体框架全程自研，约 18 个文件、核心框架约 200 行。

---

## 二、项目背景

粮食安全是「国之大者」。我国粮食产量已连续多年稳定在 1.3 万亿斤以上、储备粮规模居世界前列，
但「收、储、运、加」各环节仍存在突出痛点：

- **产后损耗偏高**：储藏环节损耗约 2%~3%，全国每年因储粮不当造成的损失巨大；
- **粮情监测靠人工**：粮温、水分、虫霉测控点多面广，传统巡检费时费力、异常响应滞后；
- **储粮风险多危害大**：发热、结露、霉变、虫害一旦失守，会造成整仓粮食降等报废；
- **质量安全门槛高**：真菌毒素、重金属等指标专业性强、限量标准繁多；
- **仓储管控不智能**：智能通风、充氮气调、谷物冷却等「科技储粮」技术落地不足；
- **轮换决策靠经验**：宜存/不宜存判定与轮换计划缺少量化依据。

这些痛点的共同特点是**专业门槛高、数据分散、需跨领域协同**，正是「大模型 + 多智能体」擅长的场景。

## 三、要解决的问题

| 问题 | 目标 |
|------|------|
| 粮情监测滞后、异常发现晚 | 实时研判发热、结露、霉变等异常粮情 |
| 质量指标多、判定难 | 依据国标自动判定等级与储存品质 |
| 虫霉防治无量化依据 | 按密度分级给出熏蒸/气调方案 |
| 仓储损耗高、管控粗放 | 智能通风/气调/谷物冷却，量化降损空间 |
| 储备轮换靠经验 | 基于品质判定给出轮换计划 |
| 多源风险协同研判难 | 综合评分、分级预警、输出处置预案 |

## 四、完成的主要内容

### 4.1 自研轻量多智能体框架（agent/）

- 实现 `Tool / Agent / Supervisor` 三层抽象与统一 **ReAct 决策循环**；
- 以「**子智能体即工具**」实现主控对 6 个专职子智能体的层级委派与结果汇总；
- 采用**两阶段输出**：工具循环非流式（稳定）、最终回答真流式（体验好）；
- 通过结构化 JSON（`{"action":"tool"|"finish"}`）决策，不依赖原生 function-calling，
  兼容任意 OpenAI 兼容模型；核心约 200 行，不依赖 LangChain/LangGraph 等重框架。

### 4.2 粮食领域数据与工具（data/mock_data.py）

- 构建 3 库点（平房仓 / 浅圆仓 / 立筒仓，小麦 / 稻谷 / 玉米）储粮数据模型；
- 实现 8 个纯函数领域工具：粮情测控、质量检测、国标限量、虫霉监测、仓储管控、
  储备轮换、综合风险评估、可视化概览；
- 数据贴近国标：安全水分、真菌毒素限量（GB 2761）、重金属限量（GB 2762）、
  虫害密度分级、储存品质判定（宜存/不宜存）。

### 4.3 FastAPI 流式后端（app.py）

- `asyncio.Queue` + 后台任务解耦智能体执行与 SSE 推送；
- 定义 `agent / tool / tool_result / text / error / done` 事件协议；
- 提供 `/api/chat`（流式问答）、`/api/overview`（可视化数据）、`/api/agents`、`/api/health`。

### 4.4 DeepSeek 风格前端（static/）

- 粮仓绿 × 麦穗金主题，深色侧边栏 + 浅色主区，简洁现代；
- 侧边栏：会话历史、智能体团队、粮情监测概览（库点切换 + 储粮状态徽标 + KPI +
  仓温/粮温/仓湿 24h 曲线 ECharts）；
- 主区：真流式问答、可折叠「思考过程」轨迹、手写 Markdown 渲染器、多会话 localStorage 持久化。

### 4.5 测试与验证（tests/）

- 用 `StubLLM` 注入实现**无 Key 全链路测试**（5 个用例全部通过）；
- 接入 DeepSeek 真实模型完成**端到端验证**（见下）。

## 五、实现的功能

1. **粮情实时监测**：粮温/水分/仓湿/粮堆气体浓度分析与发热、结露、霉变风险研判；
2. **粮食质量检测**：毒素、重金属、品质指标与储存品质（宜存/不宜存）判定；
3. **虫霉防治**：虫害密度分级与磷化氢熏蒸、充氮气调方案；
4. **智能仓储管控**：智能通风/气调/谷物冷却策略与损耗评估；
5. **储备粮轮换**：宜存判定与轮换计划、出入库顺序；
6. **安全预警与应急**：综合风险评分、四级分级预警、处置预案与行动清单；
7. **多智能体协同**：主控自动路由，可委派多个子智能体并汇总结论；
8. **可视化面板**：粮情曲线实时展示与储粮状态一目了然。

## 六、解决了哪些问题

| 实际问题 | 解决效果 |
|---------|---------|
| 粮情研判靠人工、响应慢 | 自然语言提问 + 多智能体秒级研判发热/结露/霉变风险 |
| 质量检测判定难 | 依据国标限量自动判定等级与储存品质 |
| 虫霉处置无依据 | 按密度分级输出熏蒸/气调量化方案 |
| 仓储损耗高 | 给出智能通风/气调/谷物冷却策略，量化降损空间（储粮损耗可从 2%~3% 降至 1% 以下） |
| 轮换靠经验 | 基于品质判定给出轮换计划与出入库顺序 |
| 多源风险协同难 | 综合评分 + 分级预警 + 处置预案一体化输出 |

### 端到端验证结果（DeepSeek 真实模型）

输入「评估储备库 C 的粮情安全风险」，系统自动完成：主控路由 → 安全预警智能体自主调用
`assess_risk`、`get_grain_condition`、`get_pest_monitor` 3 个工具 → 输出：

- **风险评分 18/100，高风险（Ⅳ级）**，识别五重隐患叠加的「复合型粮情风险」；
- 量化风险表（粮温 32.1℃、水分 14.6%、虫害 18 头/kg、局部曲霉、轻度不宜存）；
- 分级处置建议（立即控温降水 → 短期治虫防霉 → 中期轮换出库）与 7 项行动清单。
